## 2. Ringkasan Dasar Teori

Entity Relationship Diagram (ERD) merupakan diagram yang digunakan untuk menggambarkan struktur data dalam suatu sistem basis data. ERD terdiri dari entitas, atribut, dan relasi yang menunjukkan hubungan antarentitas.

Entitas merupakan objek yang datanya disimpan dalam basis data, sedangkan atribut merupakan karakteristik atau informasi yang dimiliki entitas. Primary Key (PK) berfungsi sebagai identitas unik setiap data, sementara Foreign Key (FK) digunakan untuk menghubungkan satu entitas dengan entitas lainnya.

Kardinalitas menunjukkan jumlah hubungan antarentitas, seperti one-to-one (1:1), one-to-many (1:N), dan many-to-many (M:N). Hubungan M:N dapat dipecah menggunakan entitas asosiatif agar atribut transaksi seperti jumlah barang dan harga satuan dapat disimpan dengan baik.

## 4. Jawaban Titik Analisis

1. **Identifikasi entitas dan kunci:** Setiap entitas memiliki Primary Key sebagai identitas unik. Foreign Key digunakan untuk menghubungkan data yang memiliki keterkaitan, misalnya `id_pelanggan` pada entitas Alamat Pelanggan dan Keranjang.

2. **Hubungan dan kardinalitas:** Hubungan antarentitas ditentukan berdasarkan proses bisnis. Satu pelanggan dapat memiliki beberapa alamat dan pesanan. Satu pesanan dapat memiliki beberapa detail pesanan, sedangkan satu barang dapat tercatat dalam beberapa detail pesanan.

3. **Penggunaan entitas asosiatif:** Detail Keranjang dan Detail Pesanan digunakan untuk menghubungkan data keranjang atau pesanan dengan barang. Entitas tersebut juga menyimpan informasi tambahan seperti kuantitas barang dan harga satuan saat transaksi.

## 5. Hasil Latihan dan Modifikasi

Berdasarkan aturan bisnis pada Modul 2, rancangan KlikKita Store memperhatikan beberapa ketentuan berikut:

1. Setiap barang harus memiliki SKU yang unik.
2. Kuantitas barang harus berupa bilangan bulat positif.
3. Satu pesanan memiliki batas maksimal delapan baris detail barang.
4. Stok barang tidak boleh bernilai negatif.
5. Harga barang saat transaksi disimpan pada Detail Pesanan.
6. Alamat penerima disimpan sebagai snapshot pada Pesanan.
7. Biaya pengiriman disimpan sebagai snapshot pada Pesanan.
8. Pembayaran hanya dinyatakan terverifikasi apabila status dan nominalnya sesuai dengan tagihan.
9. Nomor resi harus tersedia setelah pesanan dikirim.

Detail Pesanan berfungsi menyimpan jumlah barang dan harga satuan pada saat transaksi berlangsung. Dengan demikian, perubahan harga barang di kemudian hari tidak mengubah catatan transaksi sebelumnya.

### 6.2 Deskripsi Proyek

KlikKita Store merupakan rancangan sistem informasi toko daring yang digunakan untuk mengelola data pelanggan, alamat, barang, keranjang belanja, pesanan, pembayaran, dan pengiriman.

Perancangan ERD dilakukan untuk menggambarkan struktur data dan hubungan antarentitas sebelum diterapkan ke dalam basis data relasional.

### 6.3 Entitas dan Atribut

| Entitas | Atribut Utama |
|---|---|
| Pelanggan | `id_pelanggan` (PK), nama_pelanggan, email_pelanggan, no_hp_pelanggan |
| Alamat Pelanggan | `id_alamat` (PK), `id_pelanggan` (FK), penerima_alamat, alamat_lengkap, kota_alamat, kode_pos |
| Barang | `id_barang` (PK), sku_barang, nama_barang, harga_barang, stok_barang |
| Keranjang | `id_keranjang` (PK), `id_pelanggan` (FK), tanggal_dibuat, status_keranjang |
| Detail Keranjang | `id_detail_keranjang` (PK), `id_keranjang` (FK), `id_barang` (FK), qty_detail_keranjang |
| Pesanan | `no_pesanan` (PK), `id_pelanggan` (FK), tgl_pesanan, status_pesanan, alamat_pengiriman_pesanan, ongkir_pesanan |
| Detail Pesanan | `id_detail_pesanan` (PK), `no_pesanan` (FK), `id_barang` (FK), qty_detail_pesanan, harga_satuan_pesanan |
| Pembayaran | `id_pembayaran` (PK), `no_pesanan` (FK), waktu_bayar, nominal_pembayaran, metode_pembayaran, status_pembayaran |
| Pengiriman | `id_pengiriman` (PK), `no_pesanan` (FK), kurir_pengiriman, no_resi, tanggal_kirim, status_pengiriman |
