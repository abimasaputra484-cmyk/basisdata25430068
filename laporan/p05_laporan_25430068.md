## 1. Tujuan Praktikum

1. Menerjemahkan skema relasional hasil normalisasi menjadi struktur tabel menggunakan perintah DDL.
2. Menentukan tipe data yang sesuai dengan karakteristik setiap atribut.
3. Menerapkan constraint PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, DEFAULT, dan CHECK.
4. Memahami penggunaan ALTER TABLE dan DROP TABLE untuk mengubah maupun menghapus struktur tabel.
5. Memastikan hubungan antartabel berjalan sesuai rancangan ERD dan aturan bisnis.

## 2. Ringkasan Dasar Teori

Data Definition Language (DDL) merupakan bagian dari SQL yang digunakan untuk membuat, mengubah, dan menghapus struktur basis data. Perintah DDL yang digunakan dalam praktikum ini meliputi CREATE TABLE, ALTER TABLE, dan DROP TABLE.

Dalam pembuatan tabel, tipe data harus disesuaikan dengan karakteristik atribut. VARCHAR digunakan untuk teks dengan panjang bervariasi, INT untuk bilangan bulat, DATE dan DATETIME untuk tanggal atau waktu, sedangkan DECIMAL digunakan untuk nilai uang agar hasil penyimpanan lebih akurat.

Constraint berfungsi menjaga integritas data. PRIMARY KEY mengidentifikasi setiap baris secara unik, FOREIGN KEY menghubungkan tabel, UNIQUE mencegah nilai kembar, NOT NULL mewajibkan pengisian atribut, DEFAULT memberikan nilai awal, dan CHECK membatasi nilai sesuai aturan tertentu.

## 4. Jawaban Titik Analisis

**Titik Analisis 1:**

Foreign key `fk_detail_penjualan` menggunakan ON DELETE CASCADE karena detail penjualan merupakan bagian dari nota. Jika sebuah nota dibatalkan dan dihapus, data detail yang hanya memiliki arti sebagai bagian dari nota tersebut juga perlu ikut dihapus.

Sebaliknya, foreign key barang tidak menggunakan ON DELETE CASCADE. Data barang yang pernah tercatat dalam transaksi tidak boleh dihapus secara otomatis karena dapat menyebabkan hilangnya riwayat penjualan. Barang yang sudah tidak dijual sebaiknya dinonaktifkan, bukan dihapus.

**Titik Analisis 2:**

Penghapusan nota dapat menghapus detailnya karena hubungan tersebut menggunakan ON DELETE CASCADE. Namun, penghapusan petugas yang sudah pernah melayani transaksi ditolak karena tabel penjualan masih merujuk pada identitas petugas tersebut. Cara yang tepat adalah mengubah status petugas menjadi tidak aktif agar riwayat transaksi tetap terjaga.

## 5. Hasil Latihan dan Modifikasi

1. Constraint CHECK digunakan untuk mencegah nilai stok barang bernilai negatif.
2. Constraint UNIQUE diterapkan pada kode barang, nomor nota, NIM anggota, dan atribut lain yang harus memiliki nilai berbeda.
3. Constraint CHECK pada jumlah detail memastikan kuantitas harus lebih besar dari nol.
4. Foreign key diterapkan untuk menjaga hubungan antara tabel induk dan tabel anak.
5. ON DELETE CASCADE digunakan pada detail transaksi yang bergantung pada transaksi induknya.

## 7. Pembahasan dan Kendala

Dalam praktikum ini, hal yang perlu diperhatikan adalah urutan pembuatan tabel. Tabel induk harus dibuat sebelum tabel anak agar foreign key dapat merujuk pada tabel yang sudah tersedia.

Pemilihan tipe data juga harus disesuaikan dengan kebutuhan. DECIMAL digunakan untuk harga dan nominal pembayaran, sedangkan VARCHAR digunakan untuk nomor telepon, kode, dan informasi teks.

Kendala yang mungkin muncul adalah kesalahan ketika membuat foreign key akibat tipe data yang tidak sama, nama kolom yang tidak sesuai, atau tabel induk belum dibuat. Oleh karena itu, struktur tabel perlu diperiksa kembali menggunakan SHOW CREATE TABLE.
