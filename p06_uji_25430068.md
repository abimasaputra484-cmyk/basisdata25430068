## SQL pengujian negatif (jalankan satu per satu)

```sql
USE db_klikkita_store;

-- KK-06: email duplikat
INSERT INTO pelanggan
(nama_pelanggan,email_pelanggan,no_hp_pelanggan,tgl_daftar_pelanggan)
VALUES ('Tes Duplikat','andi.pratama@example.com','080000000001','2026-10-30');

-- KK-07: SKU duplikat
INSERT INTO barang
(sku_barang,nama_barang,kategori_barang,harga_barang,stok_barang)
VALUES ('ATK001','Barang Duplikat','Alat Tulis',1000,10);

-- KK-08: harga negatif
INSERT INTO barang
(sku_barang,nama_barang,kategori_barang,harga_barang,stok_barang)
VALUES ('TEST08','Barang Harga Negatif','Alat Tulis',-1000,10);

-- KK-09: qty keranjang nol
INSERT INTO detail_keranjang VALUES (1,3,0);

-- KK-10: pelanggan tidak ditemukan
INSERT INTO pesanan
(no_pesanan,id_pelanggan,nama_penerima_pesanan,alamat_pengiriman_pesanan)
VALUES ('TEST-KK-10',99999,'Penerima Tes','Alamat Tes');

-- KK-11: qty detail pesanan nol (gunakan pesanan yang ada)
INSERT INTO detail_pesanan
(no_pesanan,id_barang,nama_barang_snapshot,qty_detail_pesanan,harga_satuan_pesanan)
VALUES ('KK-20261001',8,'Mouse Pad',0,18000);

-- KK-12: nominal pembayaran negatif
INSERT INTO pembayaran (no_pesanan,metode_pembayaran,nominal_pembayaran)
VALUES ('KK-20261001','QRIS',-1);

-- KK-13: aturan stok tidak dijaga oleh constraint lintas tabel.
-- Gunakan transaksi uji tersendiri dan rollback agar data tidak tertinggal.
START TRANSACTION;
INSERT INTO detail_pesanan
(no_pesanan,id_barang,nama_barang_snapshot,qty_detail_pesanan,harga_satuan_pesanan)
VALUES ('KK-20261001',7,'Lampu Belajar LED',300,85000);
ROLLBACK;
```

## Catatan analisis
Struktur saat ini memiliki CHECK untuk memastikan qty detail positif dan stok barang tidak negatif. Namun, CHECK tersebut bekerja pada baris/tabel masing-masing. Belum ada aturan database yang memastikan `qty_detail_pesanan` tidak melebihi `stok_barang`. Karena itu, KK-13 merupakan contoh *design debt*: aturan ketersediaan stok perlu ditangani melalui transaksi/prosedur/trigger atau logika aplikasi pada pengembangan berikutnya. Pengujian KK-13 harus dilakukan dengan transaksi dan `ROLLBACK`.
